# TGIQ Football Database & Broadcast Graphics

A producer workspace and clean 1920 × 1080 broadcast output for THE GAME IN QUESTION. ESPN browsing works without an API key. The verified catalogue is Premier League and LaLiga; coverage is explicit rather than worldwide.

## Run locally

Requires Node.js 24 or newer.

```sh
npm ci
npm run setup
npm run dev
```

Open http://localhost:3000. The setup command creates private local producer credentials in `.data/local-access.json`. Open that file locally for the sign-in password. Do not share it or commit `.env.local`/`.data`. Episodes, uploaded media, source cache and on-air state persist in `.data/tgiq.sqlite` across restarts. A configured production PostgreSQL connection takes priority for a production run; keep its private environment file separate when you want an isolated local database.

For a local production run:

```sh
npm run build
npm start
```

Select a competition and season, open a team, open its squad and choose a player. Prepare the graphic, edit it, **Preview**, then **Take Live**. Browsing and editing do not alter the on-air snapshot. **Output link** creates and copies a read-only OBS/studio URL; creating another link revokes the previous one. Output is blank only after **Clear** or when access is invalid. Use an OBS browser source at 1920×1080. Sidebar cards retain 9:16 proportions with left/right placement and transparent or navy background.

Create an episode in the right column, add graphics to its rundown and use **Update saved** after edits. Saved snapshots do not refresh automatically. **Refresh Data** deliberately updates source values while retaining editorial overrides; **Revert to source** removes those corrections. **Freeze Data** disables source refresh; already prepared snapshots remain usable. Episode duplicate/archive, item reorder/duplicate/delete with undo, preflight and schema-versioned JSON import/export are included.

**Shortcuts:** Alt+P Preview, Alt+Enter Take Live, Alt+C Clear. They are disabled while typing. The preview uses the same renderer as output. Output never displays producer errors or loading panels.

## Configuration and deployment

See [.env.example](.env.example), [storage and access](docs/STORAGE_AND_ACCESS.md), [deployment status](docs/DEPLOYMENT.md) and [build evidence](docs/BUILD_EVIDENCE.md).

Production is available at https://tgiq-football-database.vercel.app. Private sign-in details are in `.data/production-access.json` on the build computer.

A new deployment requires a durable PostgreSQL `DATABASE_URL`, new `SESSION_SECRET`, scrypt `PRODUCER_PASSWORD_HASH`, and exact `APP_ORIGIN`. SQLite is explicitly refused on Vercel. Production database setup is explicit: run `node --env-file=.env.production.local scripts/db-migrate.mjs` before deploying to a new PostgreSQL database. Request startup does not run database setup. `DATABASE_URL_UNPOOLED` takes priority when explicitly set, followed by `DATABASE_URL`, then `DATABASE_URL_POOLED`. This build uses the verified working direct connection to its dedicated database. Optional `BLOB_READ_WRITE_TOKEN` puts uploads in object storage; otherwise the durable relational database stores the image bytes and origin/usage metadata. Uploaded media is authenticated; output links provide read-only access. No provider key is exposed in client code. API-Football/Sportmonks are typed extension boundaries, with no authenticated optional adapter connected in this new build.

An already open output browser keeps its last approved frame and caches already loaded media/fonts where the browser permits it. Loading or reloading the application shell requires a server connection; no fully offline reload is promised. This helps an existing output device survive a connection interruption. It is not fully offline remote control: login, browsing uncached entities, saving, changing program and another device's first connection need the server. Preflight applies to the device where it runs; check the actual output browser before filming. Revoked output access clears on reconnect.

Financial/ownership/transfer/editorial content requires source URL, attribution and reporting date. Reported fees are labelled separately. Portrait and crest access does not establish commercial image rights; retain production's usage records. Missing statistics and photos remain unavailable; test fixtures never replace live data.

## Verification

```sh
npm run typecheck
npm run lint
npm test
npm run build
# Start production locally on 3001 before the browser workflow suite:
APP_ORIGIN=http://localhost:3001 npm start -- --port 3001
npm run test:browser
# Makes real no-key provider requests:
npm run test:live
# Standalone reference-versus-component visual capture:
npm run test:graphics
```

The browser suite reads private local credentials generated by setup. For another local port set `TGIQ_TEST_URL`. It exercises real source browsing, independent output, saved overrides and episode round trips. Source capability, timeout, schema-change, scope, cup scoring, tied ranks, cache, persistence and ordering tests are independent of the external service.

Reference images live under `references/`, outside public assets. The reusable live components do not use complete reference PNGs as backgrounds. See [design evidence](docs/DESIGN_EVIDENCE.md) for the 24-image manifest, logo origin, rendering checks and screenshots.
